## 2. 我感兴趣的文章处理流程
- 获取“某日文章”后，必须先按用户偏好排序，再保存到本地；排序采用双层结构：先按网页源码中的 `category` 做主筛选，再用技术关键词做辅助加权。
- 抓取优先级：本地排序文件 > 本地缓存 > 浏览器实时抓取 > 脚本/Jina 回退。
- 阅读“第 x 篇”时，优先读取本地已保存文件（列表与文章缓存），避免重复联网抓取；只要实际读取了单篇文章，就自动将该条在对应 source JSON 中标记为 `read=true`，不论是否感兴趣。
- 展示文章时，按相关度降序一篇一篇展示，并对每篇做较详细解释 500字左右，可以拓展。
- 当用户说“看第 x 篇”时，输出固定格式：文章标题/链接、关键内容、对用户有价值的点、与用户关注方向的关系、提取的关键词（最多5个）；重点关注技术方向。
- 只有当用户明确表示“对这篇文章感兴趣”时，才将偏好记录到本地；记录分两层：`category` 作为长期筛选主键，技术关键词作为辅助标签并对重复项增加权重；单纯“阅读第 x 篇”不自动落盘。
- 感兴趣文章落盘时，不只保存文章摘要，还要记录用户围绕该文提出的关键问题、我的回答结论与要点，以及用户真正关注的重点。
- 用浏览器抓取并完成文章总结后，自动关闭浏览器，无需再次确认。
