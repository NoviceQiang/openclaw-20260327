## 2. 我感兴趣的文章处理流程
- 获取“某日文章”后，必须先按用户偏好排序，再保存到本地；排序采用双层结构：先按网页源码中的 `category` 做主筛选，再用技术关键词做辅助加权。
- 标题优先规则：凡文章标题包含“方案”一词（如“解决方案 / 应用方案 / 系统方案 / 整体方案 / 端到端方案”），在同等条件下默认前置排序，作为重点关注对象。
- 获取“某日文章”时，要意识到同一天文章可能分布在多个分页中；必须持续翻页抓取，直到覆盖该日期的全部文章，再统一排序与保存，不能只取单页结果。
- 对多页文章抓取，采用固定流程：先识别目标日期所在起止分页，再逐页抓取并保存中间结果，最后在本地合并去重、统一排序、写入正式 source JSON；若单次返回长度受限，优先使用分段抓取+本地拼接，而不是写入不完整文件。
- 某日文章抓取完成后，必须将**该日期的全部文章**保存到本地 `memory/eeworld-source-code/*.json`；JSON 内容格式应参考之前同类 source 文件，保持字段结构一致，不能只保存统计信息、摘要或前几条高相关结果。
- 抓取网页并写入 source JSON 时，默认给每条文章增加阅读状态字段：`read`（默认 `false`）与 `read_at`（默认 `null`），作为后续阅读追踪的基础字段。
- source JSON 命名规则固定为：`文章日期-抓取日期.json`，并严格参考本地既有样式（示例：`2026-3-27-2026-3-27.json`）。
  - 仅允许两段日期 + `.json`：`<文章日期>-<抓取日期>.json`；
  - 日期使用 `Y-M-D`（月/日不补零，与本地历史文件保持一致）；
  - 文件名中禁止出现 `[]`、`latest-day`、时分秒、随机后缀、额外标签。
- 同一“文章日期”若已存在旧文件，必须先做“对比 + 合并”再落盘（不可并存多文件）：
  - 先读取同日期历史文件与本次抓取结果，按 URL 去重；
  - 字段冲突时优先保留“信息更完整”的记录，但 `read`/`read_at` 必须做并集保留，不得丢失阅读状态；
  - 新抓到的文章追加进结果，缺失字段按模板补齐；
  - 合并后统一写回**同一正式文件**（`文章日期-抓取日期.json`），并删除同日期旧命名文件（含旧规则文件名）。
- 抓取优先级：本地排序文件 > 本地缓存 > 浏览器实时抓取 > 脚本/Jina 回退。
- 阅读“第 x 篇”时，优先读取本地已保存文件（列表与文章缓存），避免重复联网抓取；只要实际读取了单篇文章，就必须在该文章日期对应的 source JSON 中回写 `read=true` 与 `read_at`（ISO 时间戳），不论是否感兴趣。
- 展示文章时，按相关度降序一篇一篇展示，并对每篇做较详细解释 500字左右，可以拓展。
- 当用户说“看第 x 篇”时，输出固定格式：文章标题/链接、关键内容、对用户有价值的点、与用户关注方向的关系、提取的关键词（最多5个）；重点关注技术方向。
- 只有当用户明确表示“对这篇文章感兴趣”时，才将偏好记录到本地；记录分两层：`category` 作为长期筛选主键，技术关键词作为辅助标签并对重复项增加权重；单纯“阅读第 x 篇”不自动落盘。
- 感兴趣文章落盘时，不只保存文章摘要，还要记录用户围绕该文提出的关键问题、我的回答结论与要点，以及用户真正关注的重点。
- 用浏览器抓取并完成文章总结后，自动关闭浏览器，无需再次确认。
